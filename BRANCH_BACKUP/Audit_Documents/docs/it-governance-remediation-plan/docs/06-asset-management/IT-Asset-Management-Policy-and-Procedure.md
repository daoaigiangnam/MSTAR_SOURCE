# IT Asset Management Policy and Procedure

- **Document ID:** UOA-IT-AST-POL-001
- **Version:** 0.1 — Draft
- **Status:** For review; not approved
- **Policy owner:** IT owner (to confirm)
- **Business approver:** UOA management / delegated authority (to confirm)

## 1. Purpose

Establish accountability and traceability for IT assets from request and acquisition through assignment, maintenance, transfer, return and disposal.

## 2. Scope

Company-owned, leased or managed IT assets, including laptops, desktops, mobile devices, servers, NAS, network/security equipment, peripherals, software licenses and relevant cloud subscriptions. Actual asset scope and ownership must be confirmed against UOA records and contracts.

## 3. Policy requirements

1. Every in-scope asset must have a unique asset ID or an equivalent traceable record.
2. Record ownership, custodian/user, location, status, purchase/lease details, warranty, lifecycle and disposal evidence as applicable.
3. Asset purchases, assignments, transfers and disposal must follow approved procurement and access/equipment processes.
4. IT must not treat possession or technical administration as proof of business ownership.
5. Maintain a reconciliation between physical assets, inventory records and management tools where available.
6. Record assignment/return acknowledgements for user equipment and confirm data-handling steps before reassignment or disposal.
7. Software installations and licenses must be authorized and tracked; prohibit unapproved software and license sharing contrary to terms.
8. Assets that store or process confidential data must be protected according to classification, including access control, encryption where supported, patching and secure disposal.
9. Lost, stolen, damaged or unaccounted assets must be reported and assessed under incident management.
10. Changes to asset status and custody must have a traceable record; do not silently overwrite historical assignment or disposal data.
11. Cloud subscriptions and SaaS tenants must be included where they represent material IT services or recurring commitments.
12. Exceptions must identify the owner, risk, compensating controls, approver and expiry date.

## 4. Lifecycle process

### 4.1 Request and acquisition
- Requester states business need, user/team, required specifications and timing.
- Manager/budget owner approves need and budget according to UOA authority.
- IT validates technical fit, security requirements, compatibility and supportability.
- Procurement follows the approved purchasing process and retains quote/order/invoice/warranty evidence.
- Asset owner and asset ID are assigned when the item is received.

### 4.2 Receipt and registration
- Verify model, serial number, condition, accessories and purchase/lease reference.
- Record asset ID, serial number, supplier, received date, warranty, location, assigned custodian and status.
- Store proof of receipt in the approved repository.
- Apply asset label or other identifier where practical.

### 4.3 Assignment and use
- Confirm approved user and role.
- Complete baseline security setup and required software.
- Record user acceptance, handover date, condition and accessories.
- Link assignment to the approved request and access provisioning process.

### 4.4 Transfer, repair and return
- Record old and new custodian, locations, dates and approvals.
- For repair, document vendor custody and data exposure controls.
- On return, verify physical condition, accessories and data-handling steps.
- Remove access, revoke sessions or wipe/reset the device when appropriate to its next use and approved procedure.

### 4.5 Disposal
- Obtain disposal approval under the applicable financial/procurement policy.
- Identify storage media and data classification.
- Perform and record approved secure erasure or physical destruction, as applicable.
- Remove asset from active inventory only after evidence and approval are recorded.
- Retain disposal certificate/receipt and update software/license/subscription records where applicable.

## 5. Minimum asset register fields

| Field | Required information |
|---|---|
| Asset ID | Unique identifier |
| Category / description | Device or service type |
| Manufacturer / model | As applicable |
| Serial number / service tag | Where applicable |
| Ownership | UOA / leased / provider-owned / to verify |
| Supplier / purchase reference | Evidence reference |
| Purchase / receipt date | Verified date |
| Warranty / lease end | Date or not applicable |
| Assigned user / custodian | Approved current custodian |
| Department / business owner | Accountable business unit/role |
| Location | Site/room or controlled location reference |
| Asset status | Requested / ordered / in stock / assigned / repair / retired / disposed |
| OS / version / critical configuration | Where applicable; no secrets |
| Software/license reference | License record, not key/token |
| Security/management status | Encryption, EDR/MDM, patch status as available |
| Backup relevance | Whether data on asset is in scope |
| Last inventory check | Date and result |
| Disposal / transfer evidence | Restricted evidence reference |

## 6. Review and reconciliation

Set an approved inventory review cadence based on asset type and risk. Reconcile asset register against procurement records, endpoint/MDM inventory, network discovery and physical checks where available. Investigate duplicate, missing, unknown-owner, retired-but-active and active-but-unregistered assets.

## 7. Roles

- **Business/budget owner:** Approves need and budget.
- **IT:** Technical assessment, inventory, secure configuration and lifecycle records.
- **Procurement/Finance:** Purchasing evidence, supplier and financial records.
- **User/custodian:** Safeguards assigned assets and reports loss/damage.
- **Manager/HR/Admin:** Confirms assignment and employment-status changes as relevant.
- **Approver:** Authorizes exceptions and disposal according to delegated authority.
