# Software Requirements Specification (SRS)

## Document Status
DRAFT — working baseline; not yet approved as SRS v1.0.

## 1. Purpose
Define the functional and non-functional requirements for the RENTAL ENTERPRISE PLATFORM.

## 2. Product Scope
The platform manages rental property portfolios and the tenant lifecycle from property setup and availability through application, leasing, billing, payment, maintenance, inspection, move-out, reporting, and platform administration.

## 3. Primary Actors
- Platform Administrator
- Organization Owner
- Property Manager
- Staff
- Finance / Accountant
- Tenant
- External Integration / Partner

## 4. Core Domains
- IAM & Organization
- Portfolio / Property / Building / Floor / Unit
- Tenant / CRM
- Application / Screening
- Lease / Move-in / Move-out
- Meter
- Pricing / Billing / Invoice / Payment / Deposit / AR / Expense
- Maintenance / Asset / Vendor / Inventory / Inspection
- Document
- Notification / Communication
- Workflow / Automation
- Reporting / Analytics
- Integration / AI

## 5. Requirement Convention
Each approved requirement receives a stable identifier, for example:
- REQ-IAM-xxx
- REQ-PROPERTY-xxx
- REQ-UNIT-xxx
- REQ-TENANT-xxx
- REQ-LEASE-xxx
- REQ-BILL-xxx
- REQ-PAYMENT-xxx
- REQ-MAINT-xxx

## 6. Requirement Lifecycle
IDEA → ANALYSIS → DRAFT → APPROVED → IMPLEMENTED → TESTED → UAT → FROZEN → RELEASED

## 7. Traceability
Approved requirements must map to applicable use cases, business rules, design artifacts, database/API components, source code, test cases, test results, and release records.

## 8. Non-Functional Requirement Categories
- Security
- Availability
- Performance
- Scalability
- Reliability
- Auditability
- Maintainability
- Observability
- Backup / Disaster Recovery
- Data Integrity
- Privacy
- Compatibility

## 9. Approval Rule
This document becomes an approved SRS baseline only after the Product Owner explicitly approves the corresponding scope in project discussion. Until then, additions and corrections are expected.
